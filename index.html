01 · Cloudflare without Alchemy

Without Alchemy, nothing checks that the config matches the code


// wrangler.jsonc
{
  "d1_databases": [
    { "binding": "DB", "database_id": "4f1c…" }
  ],
  "vectorize": [
    { "binding": "VECTORS", "index_name": "assets" }
  ]
}

Resources are created in the dashboard or with separate commands, then referenced by ID.


// Somewhere in your app
export default {
  async fetch(request, env) {
    const rows = await env.DB.prepare('…').all();
    // The config says VECTORS. This compiles and fails at runtime.
    const hits = await env.VECTOR.query(vector);
  }
};

A misspelled binding is undefined at runtime.

The config, the dashboard and the code each hold part of the setup, and you keep them in sync by hand. Alchemy replaces all three with one TypeScript file.

wrangler types can generate an Env type from this file, which helps. The config is still JSON, though. It can't be composed, and nothing checks it against the resources in your account.
01 · Alchemy

With Alchemy, the infrastructure file also defines the app's types

  • Each resource is a value. Alchemy creates it when something binds to it.
  • InferEnv derives the app's env type from the bindings.
  • alchemy plan prints the changes before applying them.
  • Stages (dev, demo, prod) are separate deployments with their own settings.
  • alchemy dev emulates D1, R2 and email locally.

The misspelled env.VECTOR from the last slide is now a type error.

Alchemy v2 is built on Effect. The stack is an Effect program, and resources are yielded from it. Step through the highlighted lines in order: resources, the Website with its bindings, the inferred type, the stack. Alchemy stores its state in the Cloudflare account, so anyone else with access can deploy.

01 · Effect

Services keep Cloudflare bindings out of app logic

The search code asks for an Embedder and a VectorIndex. Production passes in Workers AI and Vectorize; tests pass in fakes.

The search code depends on Embedder and VectorIndex. It never touches env.AI or Vectorize directly. If a required service isn't provided, the program doesn't type-check. Tests provide in-memory versions.
01 · Effect Schema

One schema gives the type and the validation

The messages are written so that a person filling in the form, or a model calling a tool, can tell what to change.
01 · Main idea

Both sides of each boundary come from one definition

So neither side can drift from the other without a build error.

Infrastructure alchemy.run.ts declares DB, AI, VECTORS
⇄
App code InferEnv types platform.env; Worker classes type their own bindings
Drizzle tables Columns, constraints and indexes in TypeScript
⇄
Database Migrations generated from the tables; queries return typed rows
Effect Schema Converted to JSON Schema for tools and structured output
⇄
Model Responses are decoded; failures come back as a list of problems
Effect Schema Converted to Standard Schema for forms
⇄
People Errors are shown per field; the server applies the same rules
Neither side of these pairs is maintained by hand. When one side changes, the other is regenerated or the build fails.

02

Why strict frameworks help AI-written code

02 · Strict frameworks

Strict checks catch the mistakes models make

Model output varies between runs, so we can't count on it being right.

The type checker, schema decoding and tests give the same answer every time. If they reject wrong output before it ships, the agent can fix its own mistakes.

We can't make an LLM deterministic. We can make the checks around it deterministic, so a wrong guess fails in a predictable place with a precise message.
02 · Failure modes

A strict stack moves failures from runtime to build time

Loose stack

Found at runtime

env.VECTOR is undefined

The model returns "tags": "cat" as a string and it gets saved

An undeclared error stops a request

Usually noticed by users after release

Strict stack

Found before deploy

Type error at search.ts:42: VECTOR isn't on WebsiteEnv

Decoding fails because tags must be an array. The error goes back to the model.

Unhandled error types fail type checking

Usually fixed by the agent before anyone sees it

A build failure points to a file and line and says what's wrong. Agents handle this kind of feedback well. They read the error, change the line and run the check again.
02 · Checks

Each check catches a different kind of mistake

Types Wrong binding names, missing fields, unhandled errors, missing services bun run check
Lint Project conventions such as design tokens, the component kit, no raw colors bun run lint
Tests Behavior, using in-memory SQLite built from the real migrations bun run test
Requests Invalid input from people or models, rejected with a list of problems strict(schema)
Deploys Resources to be created, changed or deleted, listed before any change alchemy plan
The first three run together as bun run verify, and the agent is told to run it until it passes. The last two run on every request and every deploy.
02 · Example

A renamed binding fails type checking before deploy

$ bun run check Error src/lib/server/search.ts:42:28 Property 'VECTORS' does not exist on type 'WebsiteEnv'. Did you mean 'VECTOR_INDEX'? Error src/lib/server/library.ts:17:31 Property 'VECTORS' does not exist on type 'WebsiteEnv'. Did you mean 'VECTOR_INDEX'? svelte-check found 2 errors

Illustrative output. With a JSON config, both lines would deploy and env.VECTORS would be undefined.

02 · Example

A malformed model response is rejected and sent back for a retry


{
  "alt": "Image of a cat on a windowsill",
  "name": "cat",
  "tags": "cat, kitten",
  "mood": "cozy"
}

Model response

✗ decoding failed (errors: 'all') ["tags"] Expected an array, got "cat, kitten" ["mood"] Unexpected key ["description"] Missing key → sent back to the model as the tool result ✓ second attempt decodes and is saved

Illustrative. All errors are reported together, so one retry can fix them.

The schema is sent to the model as JSON Schema, and the response is decoded against it. With errors: 'all', the model gets every problem at once. The error classes have messages written for the model to read.

02 · Conventions

Fewer ways to do each thing means fewer ways for an agent to get it wrong

  • All infrastructure is in alchemy.run.ts.
  • Every write goes through a remote function with a strict schema.
  • Migrations are generated from the tables and never edited by hand.
  • UI uses the component kit. Lint rejects hand-built widgets and raw colors.
  • Conventions are written in CLAUDE.md and enforced by lint where possible.

"A color that isn't a token doesn't exist."

From the project's lint rules

Where a convention matters, back it with a lint rule or a type. Agents follow written instructions inconsistently, but they always see a failing check.

03

Architecture

SvelteKit runs in a Worker. Everything else is a Cloudflare binding.

03 · Architecture

Every service is a typed binding on the SvelteKit Worker

The browser only talks to the SvelteKit Worker. Each service it uses is a binding declared in alchemy.run.ts and typed into platform.env. The extra Workers exist because SvelteKit's generated Worker can't consume queue messages, run on a cron, or export a Durable Object class. The model APIs and Resend are outside Cloudflare.
03 · Architecture

The layers connect through a few typed files

alchemy.run.ts Resources, bindings, stages and secrets. Exports WebsiteEnv. infra → types
app.d.ts Sets App.Platform.env to WebsiteEnv so routes get typed bindings types → app
*.schema.ts Drizzle tables. drizzle-kit generate writes migrations/, which Alchemy applies on dev and deploy. tables → SQL
*.input.ts Effect Schema for each write, wrapped in strict() for remote functions schema → forms
tools.ts Agent tools generated from the block registry and decoded before they run schema → model
Layers Turn bindings into services, e.g. workersAiEmbedder(env.AI) bindings → services
workers/*.ts Queue consumers, crons and Durable Objects, which SvelteKit's Worker can't host extra Workers
03 · Architecture

A form submission is checked at every step

BrowserSubmits the form (works without JS)
→

→

→

env.DBD1 through the typed binding

Requirements

macOS, Linux or Windows. Use a standalone terminal for the login steps, since the account pickers need arrow keys.

04 · Step 1

Install bun


# macOS / Linux
curl -fsSL https://bun.sh/install | bash

# Windows (PowerShell)
powershell -c "irm bun.sh/install.ps1 | iex"

# check the install
bun --version

bun runs TypeScript directly and replaces npm for installs and scripts.

04 · Step 2

Install Wrangler and log in


# in your project
bun add -d wrangler@latest
bunx wrangler login

Cloudflare's CLI. We use it for logs and D1 queries.


bunx wrangler tail <worker-name>
bunx wrangler d1 execute <db-name> --remote \
  --command "select count(*) from feedback"
							

# Alchemy has a separate login
bun alchemy profile edit --add Cloudflare

Opens an OAuth login in the browser and saves it to ~/.alchemy/profiles.json. Deploys don't need API tokens in environment variables.

Alchemy doesn't need Wrangler to deploy. Wrangler is still the easiest way to tail logs or query the deployed database. The Alchemy login needs the project's dependencies installed, so run it after scaffolding.
04 · Step 3

Scaffold the project with an agent

Help me build a SvelteKit app on Cloudflare with Alchemy v2, Effect 4, Drizzle on D1, and bun. Read https://alchemy.run/getting-started and https://alchemy.run/cloudflare/frontend/sveltekit and follow them exactly. For anything else, look it up in https://alchemy.run/llms.txt instead of guessing URLs or APIs.

Scaffold with bunx sv create (minimal, TypeScript, Drizzle with D1), add alchemy, @alchemy.run/cloudflare, effect, and write alchemy.run.ts with a D1 database bound to a Cloudflare.Website.SvelteKit. Type App.Platform.env with InferEnv.

Effect 4 is new. Read node_modules/effect/AGENTS.md before writing Effect code. Add a verify script that runs types, lint and tests, and run it until it passes. Ask me before every deploy. Don't ask me to export API tokens.

Two parts of this prompt matter most. It points the agent at the docs, since Alchemy v2 and Effect 4 are newer than most models' training data. It also gives the agent one command that tells it when it's done.
04 · Step 4

Give the agent one command that checks its work


{
  "scripts": {
    "dev": "alchemy dev",
    "check": "svelte-kit sync && svelte-check",
    "lint": "prettier --check . && eslint .",
    "verify": "bun run check && bun run lint && vitest --run",
    "db:generate": "drizzle-kit generate",
    "plan": "alchemy plan",
    "deploy": "alchemy deploy",
    "destroy": "alchemy destroy",
    "login": "alchemy profile edit --add Cloudflare"
  }
}
  • CLAUDE.md at the root describes the stack, layout, conventions and commands.
  • The agent runs bun run verify after each change.
  • Use bun run dev. Plain vite dev has no platform.env.
04 · Step 5

Deploy


bun run dev                   # local D1, R2, email
bun run plan --stage demo     # preview changes
bun run deploy --stage demo   # apply them
bun run destroy --stage demo  # delete the stage
Plan: 3 to create + DB (Cloudflare.D1.Database) + Website (Cloudflare.Website.SvelteKit) + … Proceed? ◉ Yes ○ No ✓ DB created ✓ Website created { url: "https://….workers.dev" }

On the first deploy, Alchemy asks to install its state store in your account. Answer yes.

04 · Setup

Common problems

  • Vectorize and Workers AI have no local emulation, so dev uses real (free-tier) resources in your account.
  • Each stage reads .env.<stage>. List every setting there, even empty ones, or the stage picks up dev's value from .env.
  • Resource names come from the stack name. Renaming the project creates new, empty resources.
  • Don't edit migrations. Change the table, run db:generate and restart dev.
  • Run the login and the first deploy in a standalone terminal.

Prompt 2: schemas

Define FeedbackInput (text, trimmed, 1–280 characters, with messages a person can act on) and Classification (sentiment: positive, neutral or negative; topic; summary) in Effect Schema, and a Drizzle feedback table to match. Generate the migration. Still no UI.
